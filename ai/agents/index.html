Агенты, инструменты и MCP

Модель, workflow и агент​

Модель генерирует ответ по контексту. Workflow задаёт последовательность шагов программой: например, классификация запроса → поиск → составление ответа. Агент использует модель для выбора следующих действий и инструментов по промежуточным результатам.

Обычный цикл агента:

Цель → чтение контекста → решение о следующем действии
     → запрос инструмента → проверка прав → выполнение
     → результат в контекст → следующий шаг или завершение

Начинайте с простого решения. Если шаги заранее известны, явный workflow проще отлаживать. Агент полезен, когда путь решения зависит от обнаруженных фактов; он добавляет задержку, стоимость и новые точки отказа. См. Anthropic — Building effective agents.

Tool calling / function calling​

Приложение описывает инструмент: имя, назначение и схему аргументов. Модель предлагает вызов; код приложения проверяет запрос, исполняет операцию и возвращает результат. Сама генерация аргументов не предоставляет модели право выполнять действие.

Пример контракта инструмента для чтения задачи:

{
  "name": "get_issue",
  "description": "Прочитать задачу по идентификатору",
  "inputSchema": {
    "type": "object",
    "properties": {
      "issueId": { "type": "string", "pattern": "^WEB-[0-9]+$" }
    },
    "required": ["issueId"],
    "additionalProperties": false
  }
}

Это учебная схема, а не запрос к конкретному SDK. Даже валидный WEB-123 требует проверки доступа пользователя к этой задаче на сервере. Нельзя доверять переданному моделью userId, роли или признаку approved.

Хороший инструмент имеет узкую задачу, понятный результат, явные ошибки, тайм-аут и ограниченный размер ответа. Для записи нужны защита от повторного выполнения и журнал операции. Универсальный shell существенно шире по полномочиям, чем get_issue.

Что такое MCP​

Model Context Protocol — протокол подключения AI-приложений к источникам контекста и возможностям внешних программ.

  • Host — AI-приложение, управляющее подключениями.
  • Client — компонент подключения к конкретному серверу.
  • Server — программа, предоставляющая возможности.
  • Tools — вызываемые операции, resources — доступные данные, prompts — шаблоны взаимодействия.

Например, IDE через MCP-сервер получает задачу из трекера или выполняет поиск по документации. MCP стандартизирует взаимодействие; решение о том, какой контекст передать модели и какие действия разрешить, остаётся у приложения. См. MCP — Architecture overview.

MCP не является моделью, RAG-системой или гарантией безопасности. Локальный сервер — исполняемая программа с правами процесса; удалённый — внешняя интеграция, которой передаются данные. Проверяйте источник, область доступа, учётные данные и изменения в списке инструментов.

Память, правила и skills​

История хранит сообщения текущей работы. Память позволяет приложению выбирать сохранённые факты для будущего контекста. Правила проекта описывают соглашения, а skills в некоторых инструментах упаковывают инструкции и вспомогательные ресурсы для повторяемых задач.

Это механизмы приложения, их форматы и приоритеты не универсальны. Инструкция «перед релизом запусти тесты» полезна, но именно CI и правила репозитория должны технически препятствовать выпуску без обязательной проверки.

Как ограничивать автономность​

Для агента задают:

ОграничениеПример
Область задачиИсправить конкретный дефект, не переписывая соседние модули
Файловая системаРабочий каталог и временная директория
Сеть и секретыТолько необходимые сервисы и тестовые credentials
БюджетЧисло шагов, время, токены и стоимость
РазрешенияЧтение отдельно от записи; публикация и удаление по отдельной политике
Условие завершенияКритерии выполнены, проверки подтверждены или зафиксирована блокировка

Sandbox уменьшает последствия ошибки, но не доказывает корректность результата. Человеческое подтверждение имеет смысл на границах полномочий: например, перед необратимым удалением или отправкой данных во внешний сервис. Проверки прав выполняют вне модели.

После сбоя операция записи может уже завершиться, даже если ответ не пришёл. Перед повтором проверьте состояние или используйте idempotency key, если API это поддерживает.

Несколько агентов​

Параллельные агенты могут независимо исследовать модули или варианты решения. Цена — дополнительный контекст, стоимость, конфликтующие изменения и координация. Для одного небольшого исправления это часто лишняя сложность.

Если используете несколько агентов, разделите область записи, зафиксируйте общий контракт и выполните интеграционную проверку. Согласие нескольких моделей не заменяет тест: они могут повторить одну и ту же ошибку.
